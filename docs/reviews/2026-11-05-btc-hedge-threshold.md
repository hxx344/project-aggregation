# BTC 与净敞口对冲阈值

风险等级 R3。基线 `f8f009f290b77e45fc526dfbfe1a784d82820520`。用户要求移除 ETH，新建研究仅 BTC，并指定默认对冲阈值为 1,000 USDC。

## 变更前对齐

- 新实验、配置和行情订阅只允许 BTC；旧 ETH 会话、库存及归档保留历史身份与原始报告，不装入新引擎。
- 配置新增 `hedgeThresholdNotional:1000`，单位为 USDC 名义额，允许 0，且不得大于 `maxUnhedgedNotional`。风险上限独立保持，不因阈值而放宽。
- 阈值比较为 `abs(BN + Lighter 净数量) × 新鲜 Lighter 中间价`，使用精确计算，多空对称。低于不提交新 IOC；等于或超过则按完整净数量对冲，不只对冲超出阈值的部分。价格失效不能当作低于阈值。
- 已提交 IOC 保持原参数与延迟；终态后重新判断残余。部分/零成交/超时仍记录失败事实；新鲜估值证明已低于阈值后结束本轮尝试预算，第三次部分成交降到阈值以下不能提前阻断。再次达到阈值从新需求开始。已存在的完整 IOC 成功语义保留。
- 未达到阈值时继续受现有库存与当前/预计净敞口额度约束，页面显示「低于对冲阈值，继续报价」，不伪装为正在执行对冲。阈值接近风险上限且受最小下单量限制时，可能先限制加仓侧，不突破额度或提前对冲。
- `schema:2` 保持。新 API 配置要求完整新字段及 BTC-only；旧 v2 当前配置读取时升级为 BTC，阈值取 `min(1000, 原净敞口上限)`，保留已设风险上限。旧 v2 报告允许原 BTC/ETH 与缺失阈值，缺失表示原来的即时对冲，不回写历史假设。
- 报告 `inventory` 增加 `residualNotional:number|null`（绝对净敞口的 USDC 名义额），与阈值判断共用新鲜 Lighter 中间价；旧报告允许该字段缺失。状态沿用 `quoting` 并以 `below_hedge_threshold` 原因说明等待积累。

影响仅研究引擎、BTC 行情选择、配置与历史读取、页面及相关测试；执行适配器、真实交易能力、鉴权、外部端点和重连预算不扩展。继续仅模拟，不部署服务器。

回滚：在首次升级旧 v2 配置前，将原配置、当前会话和归档索引的 UTF-8 原文保存到 `threshold-migration-backup.json`；记录文件保持不动，迁移失败不覆盖原数据。该副本固定为首次迁移基准，不随后续会话更新。回滚时停止研究并另存之后产生的报告，再恢复所需基准文件并切回旧版；不能把首次副本当作最新快照。旧版严格配置解析器不认识新增字段，不能声称直接切旧版即可解析新版当前会话。

## 验证范围

核心覆盖正负敞口低于/等于/高于阈值、价格越线、陈旧估值、在途不可变、第三次部分成交后阈值判定、再次越线预算、lot/minimum 和额度边界；采集覆盖 BTC 元数据正常且 ETH 缺失/畸形、只订阅 BTC；管理层覆盖旧 v1/v2 参数迁移、ETH 历史与下载原样、迁移副本和失败恢复。前端覆盖 BTC-only、阈值编辑与关联校验、锁定会话阈值、未知估值和等待状态。

## 独立审查与实际证据

初审固定 tree `5a4177f885d1c3f9845fcfcc2ae5642aa1c36cf2`。隔离上下文的 `threshold_review` 未发现 P0/P1，发现一项 P2：API 接受 `1e-100` 等无法表示为内部定点数的正阈值，首次非零敞口时抛错并停止研究。修复在前后端拒绝小于 `1e-18` 的正值，0 保留即时对冲含义。独立增量 probe 确认 `1e-100`、`1e-79`、`1e-19`、`Number.MIN_VALUE` 被拒绝，0、`1e-18`、1000 正常校验和调度；最终 P0/P1/P2 为 0。初审另外实际执行核心 6 项、兼容 6 项定向检查，通过；未重复全量审查。

Codex Security 扫描 `23353b18-d08e-4a44-bf7a-94fb7c5ccce9` 已封存：复用同会话有效能力检查及上一轮 canonical 威胁模型，只审 5 个生产源码与 7 个补充文件增量，无安全候选。修复精度输入后，原安全审查者只读检查两处源码及三处测试增量，无新增候选；原封存记录保持不变。部署 ACL 未核验，不声称全仓或实盘安全证明。工具关联会话总量 4,514,151 tokens，其中缓存输入 4,401,280；该口径不是独立的模型性能比较。
