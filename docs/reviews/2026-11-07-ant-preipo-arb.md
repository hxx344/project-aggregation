# Anthropic 盘前套利（Hyperliquid io/xyz 多腿 + Binance/OKX 空腿）交付审查

风险等级 R3：新增交易所实盘下单（Hyperliquid 钱包签名）、新增凭据类型（agent 私钥）、共享账户写保护新增 authority、执行公共契约（市场、交易所、股数换算字段）扩展。基线 `3d480f5`。未改数据库表结构、鉴权中间件或部署流程；开发与测试期间不下任何真实订单。

## 影响面

- **执行交易所集合与只读集合分离。** 新增 `EXECUTION_EXCHANGES = binance/bybit/okx/hyperliquid`，只读台账、导入、只读连接、资金费与持仓页继续只用 `TRADING_EXCHANGES` 三所。自动规则使用独立的三所集合，且 `SPREADS` 不含 `anthropic`，自动规则不能选 Hyperliquid 或 Anthropic。
- **新市场 `anthropic`。** 合约：Binance、OKX 的 `ANTHROPICUSDT`（OKX `ANTHROPIC-USDT-SWAP`），Hyperliquid 的 `io:ANTH`（Entropy）与 `xyz:ANT`（trade.xyz）。按「交易所 → 支持合约」清单校验每条腿，行情接口只读取实际存在的组合。
- **股数换算。** `anthropic` 计划必须带 `shares: { outstanding, diluted }`（单位十亿股，页面默认 12.7 / 16.7，可编辑）。每单位对应股数：Binance = 流通股 S，OKX = S/10 × ctVal，io = 完全稀释股 F，xyz = 1。等量配腿与多空平衡都按「股」计算；油、海力士逻辑不变。换算是假设，不保证收敛或盈利。
- **组合规则。** `anthropic` 支持跨所两腿（两所不同、方向相反，合约可不同名）和所内两腿（仅 Hyperliquid io 与 xyz 互为多空）；不支持四腿。
- **Hyperliquid 适配器**（新文件）。固定 `https://api.hyperliquid.xyz` 的 `/info` 与 `/exchange`，只发送 `order` 与 `cancel` 两种 L1 动作；不发送划转、提现、改杠杆、授权等动作。签名为官方 phantom agent EIP-712（msgpack + nonce + expiresAfter），用官方 SDK 测试向量校验。
  - 凭据为主账户地址 + API（agent）钱包私钥。连接时要求私钥地址不同于主账户（拒绝主私钥），并以 `userRole` 证明该 agent 当前隶属此主账户；身份为主账户地址。
  - 每个写请求带 `expiresAfter = nonce + 30s`，超时后交易所拒绝执行，未知结果的观察窗口沿用执行器 ≥120 秒。
  - cloid 由执行器 clientId 确定性推导，查询、恢复、核对都按 cloid；查无（`unknownOid`）只作为执行器既有「多次查无 + 新鲜仓位一致」流程的输入。
  - 追价：只挂单（ALO）挂在同侧最优价；价格变化时按原订单号撤单，确认终结后对剩余数量重新下单（Hyperliquid 改单会换订单号，不走原生改单）。市价：IOC，价格保护为对手价 ±1%，未全部成交即暂停。
  - 逐仓：io:ANTH 只允许逐仓。适配器不改杠杆；预览展示当前杠杆类型与倍数。
- **共享写保护。** Node 与 Python `account_writer` 的 `AUTHORITIES` 增加 `hyperliquid`，身份按 `0x` + 40 位十六进制小写规范化（同 aster）。
- **HTTP。** 执行账户路由与控制面维护准入正则同步增加 `hyperliquid`；只读账户路由不变。
- **前端。** 套利交易页新增 Anthropic 面板：四所盘口、可编辑股数假设、每股价格、可成交价差与收敛空间、按股数配平；实盘执行区新增 Anthropic 市场与 Hyperliquid 钱包连接。

## 回滚

1. 停止所有包含 Hyperliquid 或 `anthropic` 腿的执行任务，等待委托核对结束；仍持有的仓位先在页面或交易所手动处理。
2. 在页面断开 Hyperliquid 实盘连接（清除已加密的 agent 私钥）。
3. 切回上一正式版。数据库表结构未变；旧版本不认识 `hyperliquid` 账户行与 `anthropic` 任务，因此必须先完成第 1、2 步，不能在有未结束任务时直接回滚。
4. 如需彻底作废，在 Hyperliquid 网页撤销该 API 钱包授权。

## 独立审查与闭环

审查者均为只读 `explorer` 子代理，上下文与作者隔离，按 `AGENTS.md`、`docs/code-review-standard.md`、`docs/code-review-checklist.md` 与路由表经验条目审查。

### 第 1 轮安全审查（`8b3ace88-cb86-4677-95d7-ddc02e8abfc7`）

范围：凭据存储与脱敏、签名、固定端点与 SSRF、路由准入、共享写保护、错误脱敏。结论：无 P0/P1；审查者独立运行签名与适配器测试 14 项全部通过。

- [P2] agent 私钥输入框 `autoComplete="off"` 会被部分浏览器忽略并提示保存密码。**已修**：改为 `name="hyperliquid-agent-key"`、`autoComplete="new-password"`。
- [P2] 同一 agent 被其他程序共用时 nonce 可能冲突。**已缓解**：连接表单提示使用专用 API 钱包；nonce 冲突由交易所明确拒绝，执行器暂停，不会重复下单。保留为已知限制。

### 第 1 轮正确性审查（`8532b259-9e2f-4fed-b7cd-7e201c4bdc4f`）

- [P1] 建单结果未知时执行器以 `id: null` 调用 `inspect`，适配器 `specOf` 把 `null` 当作非法订单号直接拒绝，未知订单永远无法按 cloid 核对，只能停在未知状态。**已修**：`id === null` 视为未提供订单号，按 cloid 查询；撤单等必须带订单号的调用仍拒绝 `null`。补充经真实适配器（伪造 fetch）的引擎恢复测试：建单传输失败后 16 次按签名中的 cloid 查询、判定未建单、不重发；临时去掉修复行该测试失败（0 次查询），恢复后通过。
- [P2] 所有 4xx 都被判为明确拒绝，408/409/425/499 等可能已执行的写请求会被当作未执行。**已修**：仅 400/401/403/404/405/413/415/422 视为网关明确拒绝，429 为限流拒绝，其余非 2xx 写请求一律按结果未知处理。
- [P2] 顶层错误正则 `/does not exist/` 过宽，可能把未知结果误判为明确拒绝。**已修**：收窄为 `/User or API Wallet .* does not exist/i`，未匹配的顶层错误按未知处理；逐单错误仍为明确拒绝，正则只用于生成中文提示。
- [P2] 追价时剩余数量低于最小下单量仍撤单，撤后无法补单，造成敞口。**已修**：撤单前检查剩余数量是否可重新下单，不可时保留原挂单；已在进行中的撤单重试不受影响。补充测试。

### 第 2 轮修复复核（`d2f3936e-1252-4177-8b06-b8f9b3299681`）

范围：只复核第 1 轮修复的增量与关联路径。结论：P1 已关闭，无未关闭的 P0/P1，五项修复正确且无回归；审查者独立运行 HL 引擎与适配器测试 21 项全部通过（未重跑作者的反证）。新提 3 个 P2：

- [P2] 剩余量低于最小下单量而跳过追价时不写任务事件，用户不知道委托为何停在旧价。**已修**：每个任务、每批、每条腿只记一次「剩余数量低于交易所最小下单量，委托保留原价、不再追价」，测试断言事件恰好一次。
- [P2] 判断能否重发与实际重发分两次读盘口，名义额恰在 10 USDC 附近且价格在两次读取间下跌时，仍可能撤单后因最小额被拒而暂停。窗口很小、结果偏保守。**登记**。
- [P2] 平仓剩余量不检查最小名义额。第三方资料（Chainstack 文档）称 Hyperliquid 仅对恰好全部平仓的只减仓单免除 10 USDC 下限，未见官方明文；若部分平仓剩余量过小，结果为重发被明确拒绝后暂停，偏保守。**登记**，未改规则。

第 2 轮的修复只新增一条去重的任务事件，不改变下单、撤单或核对行为，未再派第 3 轮审查。

### 登记的 P2 与已知限制

- 交易对元数据缓存 60 秒，资产编号与缓存比对；依赖 Hyperliquid 资产列表只追加不重排，未实现强制刷新。
- `expiresAfter` 的哈希拼接与官方 SDK 实现一致，但没有官方带 `expiresAfter` 的测试向量，测试只验证它改变哈希与签名。
- agent nonce 只在本进程内单调；外部程序共用同一 agent 时可能被交易所拒绝（不会重复下单）。
- 未做 Hyperliquid 请求额度节流与 ALO 回弹退避；1 秒追价连续运行 3600 秒约消耗初始地址额度上限 10000 次。
- 成交证明读取 `userFillsByTime` 最多 5 页 × 2000 条，交易所只保留最近 10000 条；高频其他活动或长时间暂停可能无法证明终结，此时保持未决并要求人工处理，不会误判。官方文档确认该接口包含 HIP-3 成交。
- Binance `ANTHROPICUSDT` 的实时合约元数据因公网 451 未核实；适配器接受 `PERPETUAL` 与 `TRADIFI_PERPETUAL`。
- 本地时钟未与 Hyperliquid 校准；极大的正向偏移可能削弱 `expiresAfter` 与 120 秒观察窗口的配合，其余证明仍生效。
- 撤单重试测试断言次数范围（2–5 次），未精确断言间隔。
- 本地保守上限：单笔最大 100000、最小名义 10 USDC。
- 未做受管账户写保护与引擎联动的 Hyperliquid 集成测试，也未做 OKX Anthropic 引擎端到端测试。
- 任务历史不显示股数假设与杠杆（预览中显示）。
- 第 2 轮登记的两项：追价前后两次读盘口的时间差；平仓剩余量的最小名义额规则未经官方核实。
- 股数默认值 12.7B / 16.7B 为估算；2026-11-06 的 S-1/A 未填股数与发行区间。
