### F02 / P1：Aero LP 新锁的元数据发布窗口允许两个执行者同时进入

位置：[tools/aero-lp/cli.mjs:78–89](https://github.com/hxx344/project-aggregation/blob/4e19cfd237fb0d047686f2297a0c5e1007b70950/tools/aero-lp/cli.mjs#L78-L89)。由 `53d9d423` / PR #99 引入。

同一钱包、同一数据目录的两个进程并发启动：第一个完成 `mkdirSync`，尚未写 `owner.json`；第二个读取不到 owner，直接删除并重建锁。两者随后均可继续运行，且释放锁时没有归属校验。

未修改 CLI 源码，用零余额的外部链读取夹具和调度屏障运行真实 managed 与独立 `run` 入口。两个进程同时进入 `cycle`；独立进程正常退出后，managed 仍运行而锁目录已消失，第三个进程也将失去互斥阻挡。未发送交易，不声称已出现重复实盘资金动作。

缺失或未写完的 owner 不能直接证明锁已陈旧。需原子发布/回收与唯一归属 token，释放前验证归属；补两个真实进程竞争及一个退出时另一锁仍有效的检查。不同数据目录的锁本就不互通，不在本条复现前提内。

多个质押头寸位于现价上方且下沿相同，计算每仓“进入下沿”的份额时只把该仓加入当前活跃流动性，页面却直接累加成“多个质押头寸合计”。钱包追加资金后按相同目标区间开第二个头寸即可形成该状态。

真实 `rewardView` 离线计算：池当前活跃质押流动性 100、两个区间外头寸各 200，全池每天排放 86400 AERO；每仓分别算为 57600，合计 115200，超过整个池子。两仓同时进入相同下沿时，共同分母为 500，该场景正确合计为 69120。

应在共同价格情景下计算所有头寸的分母；不能形成共同情景时不直接给出可相加总额。影响每日奖励及折算价值展示，不改变链上实际排放。

### F06 / P2：飞书发送前持久化失败，仍然向外发送

位置：[server/automation/feishu-digest.mjs:36–38](https://github.com/hxx344/project-aggregation/blob/4e19cfd237fb0d047686f2297a0c5e1007b70950/server/automation/feishu-digest.mjs#L36-L38)、[88–89](https://github.com/hxx344/project-aggregation/blob/4e19cfd237fb0d047686f2297a0c5e1007b70950/server/automation/feishu-digest.mjs#L88-L89)。由 PR #119 引入。

`persistState` 吞掉原子写失败，tick 仍执行 deliver。如果磁盘保留旧 lastSlot，发送前和发送后记录都未落盘，或两者之间崩溃，15 分钟补发窗口内重启会重复同一时间点。

真实 manager、临时目录和本地 fetch 替身复现：以目标路径无法原子替换模拟写失败，首次发送一次、记录两次写失败；恢复原有旧状态后重启，发送次数变为两次。若发送后的记录成功落盘，或首次根本没有旧状态文件，此特定路径不成立。

发送前的持久化占用必须成功才能对外发送；失败应保留之后恢复的重试资格并提示状态。发送后的历史写入可以单独处理。影响是重复通知，未证明越权或资金影响，故按 P2 登记。
