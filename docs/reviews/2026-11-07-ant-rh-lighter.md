# Anthropic 盘前套利接入 Lighter RH（Robinhood Chain）交付审查

风险等级 R3：新增交易所实盘下单（Lighter 官方 WASM 签名器）、新增凭据类型（L1 地址 + 账户索引 + API Key 索引 + API 私钥）、共享账户写保护新增 authority `rh-lighter`、执行公共契约（交易所、合约、计价币 USDG）扩展、撤单重试预算的引擎逻辑调整。基线 `5b63823`。未改数据库表结构、鉴权中间件或部署流程；开发与测试期间不下任何真实订单。

## 影响面

- **交易所 `rh-lighter`**（`https://api.rh.lighter.xyz`，链 466324，USDG 永续）。只在 Anthropic 市场开放 `ANTHROPIC`（market_id 38），报价口径与 io:ANTH 相同（每单位 = 1B 完全稀释股）。
- **市场监控**：Anthropic 价差新增 Lighter RH 腿与 K 线回补；**资产**：新增 Lighter RH 连接类型，按 L1 地址读取账户与仓位；**套利交易**：Anthropic 合约列表、实盘连接表单、预览与执行；**仓位与强平预警**：复用实盘连接的 L1 地址读取全部子账户仓位。
- **签名器**：`server/vendor/lighter-signer/` 内置官方 lighter-go（提交 `aefa968`）构建的 WASM（Brotli 压缩）与 Go 1.26.10 `wasm_exec.js`，加载前校验两者 SHA-256；在独立 worker 中运行，运行前删除线程内网络全局对象；只暴露下单、撤单、鉴权令牌三种签名，不能签转账、提现、改杠杆或换密钥。许可原文见同目录 `LICENSE` 与 `THIRD_PARTY_LICENSES.txt`（含 go-ethereum LGPL-3.0）。
- **适配器**（`server/trading-rh-lighter-execution.mjs`）：追价腿为 post-only 限价，有效期 2 小时（任务最长 1 小时）；市价腿为对手价 ±1% 的 IOC。按客户订单号撤单与核对；nonce 串行，任何未被接受的发送都重新读取。sendTx 只在明确错误码时判为拒绝，21728、5xx、无法解析等一律为结果未知；结果未知的建单在签名过期（10 分钟）+ 余量后才可能判定未建单，不重发。
- **限流**：本地每分钟 50 次（官方 60 次）滑动窗口，等待超过 8 秒即本地拒绝；429/405/23000 后冷却 60 秒。发送守卫之前的本地拒绝标记 `notSent`。
- **引擎**（`server/trading-execution.mjs`）：撤单在适配器发送前被拒（`notSent`）时退还撤单次数、保留 10 秒间隔，另设连续 30 次上限（L084）；只有真正发出的撤单才清零。其他交易所不产生 `notSent`，行为不变。
- **写保护**：Node 与 Python `account_writer` 增加 `rh-lighter`，身份为小写 L1 地址。
- **路由**：执行账户路由与控制面准入正则增加 `rh-lighter`。

## 回滚

1. 停止所有包含 Lighter RH 腿的执行任务，等待委托核对结束；仍挂着的追价单最迟 2 小时后由交易所自动过期，也可在 Lighter 网页手动撤单。
2. 在页面断开 Lighter RH 实盘连接（清除已加密的 API 私钥）；资产模块删除 Lighter RH 连接。
3. 切回上一正式版。数据库表结构未变；旧版本不认识 `rh-lighter` 账户行与任务，必须先完成第 1、2 步。旧版监控只认 Binance + Hyperliquid 的 K 线快照，回滚后会重新抓取历史（Hyperliquid 约 52 天）。
4. 如需彻底作废，在 Lighter 网页更换或删除该 API Key。

### 后续修复（交接清单 P2/P3）

- **建单已接受但未可见**：适配器对 sendTx 接受后的所有错误标记 `uncertain + accepted`；引擎记录 `acceptedAt`，在签名有效期 10 分钟 + 调用超时 + 60 秒 + 一次复查（60 秒）内按客户订单号继续查询，期间不追价、不撤单、不下新单，不暂停；窗口结束仍查无且账户不干净才暂停；账户干净时由既有 `absentCreate` 判定未送达后重新规划。用户停止与执行期限在等待前处理。
- **未送达建单（本地限速、冷却、发送前传输失败）**：不再暂停，按 rejected 结算后重新规划；间隔取 `max(10 秒, min(retryAt, 120 秒))`，不早于冷却结束（L084）；连续 30 次后暂停，任一真实发送清零；恢复任务时清零；每任务 4000 单上限不变。开发中发现该分支返回前未保存委托（`finishWrite` 先于状态更新落库），已修并登记 L104。
- **限流口径**：按官方文档，未鉴权请求按 IP 与 L1 地址计、鉴权读与 sendTx 只按 L1 地址计，标准账户 60 次/分、触发后静态冷却 60 秒（HTTP 429/405 或代码 23000）。执行端与用户自己的 App、子账户共享 L1 额度，执行端上限由 50 降到 40 次/分；全部限流来源带 `rateLimited` 与 `retryAt`。监控、仓位预警、资产都是未鉴权读，走 IP 额度，与执行端不是同一个桶，因此仓位预警保留独立冷却、不共享执行端冷却；监控与仓位预警对 23000（HTTP 400 或 200 响应体）同样冷却 60 秒；监控响应体限 2 MiB（Content-Length 预检 + 流式计数）。
- **0 值字段**：2026-11-07 用真实只读接口核对，账户、资产、仓位的数值字段为显式 0（不省略）。资产模块改为与执行适配器、仓位预警一致：缺字段即拒绝，只有 `shares` 与 `bo_positions` 可缺省，`margin_mode` 只接受 0/1，`avg_entry_price` 必填。
- **K 线与时间戳**：真实接口核实 `created_at` 为毫秒；K 线按时间连续返回，现有逐页游标可推进，空页游标持久化不需要，未改。订单 `timestamp` 按官方 Order schema 为秒，保留并新增 `>= 1e11`（毫秒）拒绝。
- **P3**：杠杆统一向下取整；断开连接调用适配器 `forget()`，清空令牌、身份、nonce、订单读缓存与共享令牌并关闭懒加载的签名 worker，代际计数防止在途请求写回；post-only 被吃穿后重挂不早于上次发送 5 秒（`RH_LIGHTER_MIN_REPRICE_MS`）；监控显示名统一为「Lighter RH」，持久化标识 `ANTHROPIC_SOURCE` 保持原值。
- RH 实际可见延迟未实测（需要真实下单，按约束未做），因此以签名有效期为上界等待，而不是调短窗口。
