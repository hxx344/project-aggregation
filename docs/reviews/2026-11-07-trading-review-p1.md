# 交易推送故障与自动减仓：合入后审查 P1 修复

风险等级 R3：交易执行适配器（Binance / Lighter 推送回退）、执行状态机（`runJob()` 外部委托处理）与 Anthropic 自动减仓规则。基线 `origin/main` `f24140d`。

## 背景

对 PR #249 之后的合入（`4efbca4` … `f24140d`）做合入后审查，核实 3 项 P1：

1. Binance 执行适配器把推送流 `invalid_data`（含格式错误帧、事件时间比校时估计超前）直接报错，引擎暂停并撤销对冲腿，违反 L103。
2. Lighter 订单快照包含账户在该市场的全部订单，一行 `client_order_index` 为 0 的手动单否决整份快照；适配器对 `invalid_data` 不回退 REST，建单在发送前失败而同批 Binance 腿已发出。
3. Binance 断线或冷却期间读到的 REST 订单写入流缓存，重连后新连接不补发断线期事件，旧状态最长 30 秒仍作为当前状态返回。

另有一项：用户自己的止盈止损或限价单使自动减仓在触发时刻抛 409，规则被静默停用。

## 修改

- Binance 推送：事件或盘口时间超前归为 `upstream`；缺失、非法时间仍为 `invalid_data`。适配器只在 `aborted` 时失败，其它推送故障关闭本次推送读取并走有界 REST 精确补读。
- 流缓存代次：新增 `orderGeneration()`；建单、改价、查询、撤单在 REST 请求前取代次，`seedOrder` 仅在仍连接且代次相同时写入，否则该订单标记为必须走 REST。
- Lighter：快照只跳过本市场本账户 `client_order_index === 0` 的手动单，其它非法行仍为格式错误；适配器把 `invalid_data` 列为可回退 REST。
- 外部委托：新增 `ExternalOrdersError`。自动减仓未达阈值时提前预警；触发时保持启用、30 秒重试，原因与事件可见且不重复记事件，仍返回风险读数。任务进行中出现外部委托时，截止前只暂停发新批次、不撤本任务余单；截止后按原路径暂停。手动任务行为不变。
- 前端：自动减仓面板显示 `live.warning`。

无数据库结构、接口路径或配置变化。
