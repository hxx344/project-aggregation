# 自动规则只观察模式（#283）

风险等级：R3。让用户持续检查开仓和平仓条件信号、连续满足次数与中断原因。观察不是虚拟持仓，也不模拟收益。

影响面：自动规则 JSON 状态、调度器、现有鉴权自动规则接口及规则页面。复用 `evaluateRule()`；观察在执行准入之前分流，只读取公共盘口，不创建任务、合约锁、账户租约或交易所写请求。独立观察事件最多保留 30 条；连续次数只在内存中保存，同一双腿时间组合计一次。

规则修改、停止、维护、缺失/过期行情、领导权丢失和重启清零连续次数。观察转实盘使用独立操作与确认，必须等待转换后的新盘口，并重新经过现有执行预检；持仓、执行中和待核对规则不允许切换为观察。异步读取前后的规则版本必须一致。

回滚：不更改 SQLite 表结构；观察规则旧 `enabled` 列固定为 0，旧代码会把它当作停用规则。旧记录默认为实盘。回滚前停止观察；已明确转入实盘的规则遵守现有实盘停用与任务处理流程。以旧版实现读取新观察记录验证不会触发。

必要检查：观察零副作用、采样去重及中断、转换明确确认/新盘口、修改和转换的迟到读取、重启及旧代码回滚；复用实盘规则回归。前端类型/生产构建及工作台规则入口交互。固定差异独立审查与安全审查。Windows 原生执行，无真实交易、服务器部署或 WSL。

已运行（Windows 原生）：`node --test tests/trading-auto.test.mjs` 31/31；自动规则 HTTP 鉴权/慢请求退出测试 2/2。包含真实内存 SQLite 和共享保护库，观察前后没有任务、symbol locks、私有账户读取、共享库变更或交易写调用。真实基线 `0243193` 的 `createTradingAuto` 通过 data URL 导入读取新观察记录，保持停用且盘口/建任务调用均为零。
