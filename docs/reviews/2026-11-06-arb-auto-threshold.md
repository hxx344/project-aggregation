# 套利交易阈值自动开平仓交付审查

风险等级 R3（无人值守实盘下单、执行状态机、新增数据库表与写接口）。基线 `bf02adc34edc6996b272738d5482b3f80f8c85a4`，合并前变基到 `0561118`（只含构建脚本与流水线改动，与本次文件不重叠）。范围：`server/trading-auto.mjs` 规则引擎、`server/trading-execution.mjs` 自动任务与发送前复核、`server/trading-execution-exchanges.mjs` Binance 显式挂单价、`server/runtime/data-plane.mjs` 路由与停机、`src/TradingAutoRules.tsx` 页面及相关测试。未改依赖、鉴权中间件或部署流程，未下任何真实订单。

## 影响面

- 新表 `execution_auto_rules`（`CREATE TABLE IF NOT EXISTS`），不改既有表结构；执行任务 JSON 增加可选 `auto` 字段，旧任务不受影响。
- 新接口 `GET /api/trading/execution/auto`、`POST /auto/rules`、`PUT|DELETE /auto/rules/:id`、`POST /auto/rules/:id/(enable|disable|reset)`，沿用登录会话、同源与 CSRF，读完请求体后复查会话。
- Binance 适配器新增可选 `limitPrice`：只用于自动任务的追价腿，发送 `LIMIT`、`GTX`、`price`，且必须严格在界限内；不带该字段时（手动执行）仍为 `priceMatch=QUEUE`，行为不变。
- 自动任务走现有执行器：账户写入守卫、合约锁、连接修订、维护准入（`executionEntries.run`）、发送前所有权检查全部沿用。手动执行路径只在恢复自动任务时清除自动复核条件，其余行为不变。
- 规则只在本服务成为执行主节点时触发；维护期间不触发；同一交易所与品种同时只允许一条启用或持仓中的规则。

## 独立审查与闭环

每轮新开只读审查者，只交接本轮差异与已关闭问题。

| 轮次 | 发现 | 处理 | 状态 |
| --- | --- | --- | --- |
| 经验核对 | 平仓可能落到更换后的账户；停机时在途触发仍可建任务 | 开仓完成时记录连接修订与身份，持仓期间连接变化转待核对、不平仓；`stop()` 同步关闭并等待在途触发 | 关闭 |
| 第一轮 R3 | 3 个 P0（账户绑定、发送时阈值、停机）、2 个 P1（上传途中登出、过期盘口显示满足）、2 个 P2（守卫测试、十进制比较） | 发送前每批用最新盘口复核；`signedBody()` 复查会话；服务端标记过期读数；前端改用 BigInt 精确比较；补真实账户写入守卫测试 | 关闭 |
| 第二轮 R3 | P1：追价改单可越过阈值；P2：2xx 响应解析失败被当成失败、测试夹具未调用 `beforeMutation` | `boundsFor()` 按余量给两腿设追价界限，追到界限保持原价；2xx 不可读归为结果未知并重读；夹具调用 `beforeMutation`，并以变异验证确认测试有效 | 关闭 |
| 安全差异审查 | P2：`market` 传数组可绕过同品种互斥与数量单位判断 | 四个枚举字段都要求为字符串，补测试 | 关闭 |
| 第三轮 R3 | P1：负阈值下界限 ≤0，单腿被本地拒绝而另一腿已成交；P1：慢腿使旧盘口与新盘口配对；P3：文案 | 界限至少钳制到 1 tick，发送任一腿前统一校验全部界限；执行器记录盘口本地接收时间，两腿都须在 1.5 秒内读到；文案更正 | 关闭 |
| 第四轮 R3 | P1：Binance `priceMatch=QUEUE` 按撮合时价格成交，界限没有传到交易所；P1：`received` 晚于真实盘口接收（合约规则缓存过期时）；P1：校时重试不复查 1.5 秒窗口 | Binance 自动任务建单与改单改用界限内的显式只挂单价格（复核时的同侧最优价），适配器发送前硬校验、改单回包价格不符视为结果未知。成交价因此不可能越过界限，与盘口新旧及重试时机无关；1.5 秒窗口保留为附加新鲜度检查，只影响成交概率 | 关闭 |
| 第五轮 R3 | 无 P0–P3。核实建单、改单、校时重试、重启恢复与核对路径都保留 `limitPrice` 与界限；FAPI 与 PAPI 只发互斥的 `price` 或 `priceMatch`；改单回包按委托价比较，部分成交与全部成交不误判；钳制后 16,000 组界限推演无失败 | — | 通过 |

安全差异审查按 STRIDE 与 OWASP 核对了鉴权与会话、维护准入、交易边界、SQL 参数化、字段白名单、请求体与规则数量上限、信息泄露和前端文本渲染，未发现高或严重问题。

## 登记的 P2 / 已知限制

- 价格界限由交易所侧落实：Binance 与 OKX 用界限内的显式只挂单价格，Bybit 用原生 `maxChasePrice`。行情越过挂单价时只挂单被拒，任务暂停、规则转待核对，可能留下已成交的另一条腿，需要人工处理。市价单不设界限，可能有滑点。
- 1.5 秒窗口按 `market()` 完成时刻计时，合约规则缓存过期时可能晚于真实盘口接收；在显式价格之下只影响成交概率，不影响价差保证。
- 创建请求响应丢失时页面重读状态，但不带幂等键；重复提交最多多出一条停用规则（启用规则受同品种互斥约束）。
- 连续满足次数只在内存中累计，重启后从零开始；自动接口未单独压缩，12 条规则规模下体积有限。
- 既有 `tests/trading-okx.browser.mjs` 的“开仓方向”下拉选择器与当前按钮组不符，此前即失败，本次未改动该页面部分。

## 回滚

1. 在页面停用全部自动规则；在执行任务中等待或停止仍在运行的自动任务。
2. 处于持仓或待核对的规则，先用手动执行平掉或核对实际仓位，再重置规则。
3. 切回上一正式版。`execution_auto_rules` 表保留，旧版本不读取；旧版本加载带 `auto` 字段的任务时只当普通任务处理，且重启会暂停在途任务，因此必须先完成第 1、2 步，不能在有自动持仓时直接回滚。
