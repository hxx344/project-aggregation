# 自动化环境配置与部署流程架构

## 概述

本文档说明 project-aggregation 的自动化部署架构：从本地开发到生产发布的完整流程，包括依赖管理、配置渲染、构建验证、打包发布与服务激活的触发条件、执行顺序、参数校验、失败回滚与可重复执行机制。

### 设计目标

1. **环境一致性**：开发、测试、生产使用统一流程，差异由配置声明，不靠文档约束
2. **可重复执行**：幂等设计，同样输入多次执行结果相同，支持中断重试
3. **失败可回滚**：配置与打包阶段自动回滚，服务切换由安装器保障
4. **清晰职责**：流水线编排阶段顺序与依赖，安装器负责服务器激活，不重复实现
5. **可观测性**：结构化日志、状态文件、journal 记录，支持事后审计与诊断

## 整体架构

```
┌─────────────────────────────────────────────────────────────────┐
│                        部署流水线层                                │
│  deploy/pipeline/: 阶段编排、配置管理、执行控制、状态追踪           │
└────────────┬────────────────────────────────────────────────────┘
             │
             ├─> preflight: 工具链版本、Git 状态、配置完整性
             ├─> deps:      pnpm install --frozen-lockfile
             ├─> config:    渲染 .env，写入系统路径（需 --apply）
             ├─> build:     构建工作台与五个内置模块
             ├─> verify:    类型检查、行为测试
             ├─> package:   打包发布清单与运行包
             ├─> publish:   发布到 GitHub Release（需确认）
             └─> activate:  调用安装器切换服务（需 --apply）
                            │
                            ↓
┌───────────────────────────────────────────────────────────────────┐
│                       服务器安装器层                                 │
│  deploy/install-all.sh + install.sh: 源码/CI 包获取、缓存、健康检查  │
└───────────────────────────────────────────────────────────────────┘
