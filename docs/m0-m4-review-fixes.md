# M0–M4 合入审查修复

本批基于 `6ab243e`，按 R3 处理。目标是保留切流/回滚后的页面可用性、Greeks 原意图保护和有界 API 关闭，并核实跨 API 更新准入的共享状态。来源是本次 M0–M4 合入审查，不推进历史复盘检查点。

## 变更与回滚

| 范围 | 行为与失败边界 | 回滚 |
| --- | --- | --- |
| 静态资源 | 只从自身及 current/previous/两个槽指向的合法发布目录读取分包；不扫描其他版本、不缓存链接目标，拒绝路径穿越和目录内链接 | 保留发布目录和槽链接；旧程序不具备新资源查找能力，不能保证回退旧二进制后新页面仍可延迟加载 |
| Greeks 改单 | 原单日志保存严格递增序号后才能 prepare/发送；同单 sending/unknown、损坏序号、落盘失败继续拒绝，旧摘要 ID 仍按原单核对 | 不回滚交易数据或重置序号；旧日志读取器允许保留额外字段，未决操作保持原样 |
| API 排空 | 状态流先停连接和计时器，pending 与协调器共享收尾预算；关闭后不执行排队维护调用、迟到写库或新的特权申请 | 回退程序，不改系统单元的既有停止预算 |
| Portal 撤销 | 首次撤销、后台重试、关闭均不等待 SQLite 写锁；本地拒绝及跨实例成功撤销语义保留 | 只回退程序，现有授权表不迁移 |
| 共享维护准入 | settings 保存随机代号和独占请求所有者（进程身份、准备/已发送阶段及原状态）；事务内拒绝仍活跃的竞争者，包括同计划重入；状态/check/错误恢复只改同一代，退休必换代 | 无表结构迁移；保留 owner、token 和 pending，旧程序忽略新增键；回退须整体重启，不能让旧协调器与新协调器长期并存 |

这些共享源码输入会让安装器选择整体更新，不作为新旧协议混跑的 API-only 更新。服务器更新仍由用户执行。

## 跨 API 竞态的证据边界

Windows 离线使用两个 Hub SQLite 连接、真实 Node 协调器与 runtime hooks、实际 Python Coordinator.apply/run/file_lock。旧 API 的停机证据延迟失败，另一个 API 对同计划同模式已排队；修复前 worker 经过 stack lock、计划哈希、发布材料和安装身份检查后，安装前读到维护为 false。最终实现把竞争者在活 owner 期间统一拒绝；第一条失败完成后，另一实例可重试并在维护保持为 true 时进入安装。不能只让后申请覆盖代号：独立审查实测这种初稿在全部确定失败时会遗留维护锁，因此改为独占请求，不嵌套原状态。

确认 owner 进程死亡且尚在 preparing 时可恢复原状态；sending 则保留不确定 pending。活性证据未知按仍存活处理，Linux 核对进程启动身份以防 PID 复用；本进程另按活请求集合区分同进程重建。发送前同步持久化 sending，成功、确定失败、未知结果及关闭均退休 owner 并更换代号。未知结果仅去掉 owner，不解除维护；同计划重试和既有 root 状态恢复继续有效。关闭时 preparing 可以恢复原状态，sending 仍保留 pending，迟到 continuation 不改新实例状态。

测试保留反证：CLI 锁还活着时 worker 不进入安装；排队后安装身份改变时不进入安装。普通在线 API-only 切流已有 ACTIVE 任务，不能据此推断它必然受到该竞态影响。POSIX 专项重现中断切流保留两个 serving API、旧 keep-alive 与新连接、CLI 锁进程被 SIGKILL 的状态，且在真实 root worker 进入安装回调之前检查维护；仅安装副作用被离线回调替代。Windows 明确跳过这一项，Linux 由已安装工作区依赖的 installer-slots job 的 sudo Node 检查执行。

## 检查与独立审查

- Greeks 账户回归、订单/恢复关联测试在 Windows 原生 Python 执行；真实追价、重启、旧未决及 fsync 失败均为离线 MockTransport。
- 静态资源使用真实 API HTTP，修复前两个核心用例返回 404，修复后通过；目录 junction 边界在 Windows 执行，文件 symlink 权限不足仅跳过该子项，由 Linux CI 覆盖。
- API/Portal/更新协调器相关 Node 回归和根 TypeScript 检查按受影响范围执行，输入未变的通过结果复用。
- 新增共享协调器检查覆盖真实 root 决策、竞争申请全失败、旧 pending 恢复、迟到 status/check、事务失败、uncertain 重试、进程被终止及同进程关闭重建；Linux 另验双槽中断，现有真实 systemd 负载补充延迟分包与跨切流授权。
- `review_fixes_core` 独立只读审查 Greeks、资源回退及 systemd 测试；`review_update_fixes` 独立只读审查 API 关闭、Portal、共享维护状态及直接调用方。最终结论与真实执行命令记录在本批提交中，不能仅因本文列出检查就视为通过。
- 本机未使用 WSL、真实交易或服务器部署；必要 Linux/打包/发布检查以本批对应提交的 Checks 为准，失败先修复再发布。
