# 四模块预加载与页面保留

用户反馈四个模块都会长时间显示“正在打开项目”。旧版只在点击时创建 iframe，最多保留两个已连接页面，因此未打开的模块没有预加载，四模块轮换也会反复加载。

本次在工作台实现依次预加载、四页面保留和稳定的 iframe 插入顺序。当前点击立即开始，后台最多保留一个未完成加载；悬停或键盘聚焦提升未开始项目的优先级。隐藏和离线时停止启动新的预加载。失败、超时及不支持活动状态的页面释放队列，同一配置版本不自动反复重试，用户可以主动重新打开。

预加载只准备内置代理模块的界面与脚本。四个模块已有的桥接约定使隐藏模块默认暂停前台数据刷新，进入后再补查，服务器采集和同步保持独立。预加载不更改数据源时间、过期阈值、授权票据或登录方式。内部刷新会重新确认当前文档的桥接能力，避免旧文档状态残留。

## 浏览器对照

Windows 原生 Node，真实生产构建，Codex 内置浏览器。基线为 `6d5ae0c` 的构建；前后版本使用相同的本地合成模块。每次 launch 人为延迟 250 ms，模块 HTML 延迟 1200 ms，图片延迟 800 ms；Monitor 在 load 后 100 ms 宣告 ready，其余模块在 load 前宣告。未连接真实账户或交易服务。

计时从点击侧栏到已完成模块握手的 iframe 可见，使用页面内 `performance.now()` 与 DOM 观察记录；不包含浏览器绘制耗时或真实行情首次返回。新版先在总览完成预加载，再依次点击各模块。以下每个步骤各采样一次，属于行为对照，不是生产服务器延迟或统计分位数。

| 操作 | 旧版点击到可见 | 新版预加载后点击到可见 |
| --- | ---: | ---: |
| 首次打开 ASTER | 1786.7 ms | 2.5 ms |
| 首次打开 Monitor | 2705.7 ms | 0.8 ms |
| 首次打开 Asset | 1784.4 ms | 1.0 ms |
| 首次打开 CrossEx | 2110.0 ms | 1.4 ms |
| 一轮后再次打开 ASTER | 2086.5 ms | 1.1 ms |

新版在任何模块被点击之前，四个模块各完成一次 launch 和 HTML 加载，行情读取为零，后台 HTML 加载最大并发为一。四模块切换并返回 ASTER 后，所有页面仍只加载一次；旧版 ASTER 已加载两次。新版回到总览后，四模块读取计数保持不变。

## 验证与使用边界

- 工作台 109 项测试通过，生产构建通过；四个模块现有桥接测试共 13 项通过。
- 新增调度测试覆盖串行预加载、点击优先、快速切换的并发上限、失败后释放、不自动重试、可见性/网络门控、配置版本更新、停用/移除及未知接入排除。
- 浏览器确认 ready 早于和晚于 load 均能保留页面。内部刷新场景将图片延迟 10 秒，新文档在资源仍未加载完时已重新握手并恢复活动。
- 已连接 iframe 内部跳转至无桥接页面后，离开并再次选择该模块会创建新 launch 并恢复正常页面，不会永久保留旧文档的 ready 状态。

预加载需要准备时间，刚登录就立即点击的模块仍可能处于首次加载中。保留四页会比原先两页占用更多浏览器内存；隐藏页面暂停刷新。生产服务器的网络、模块服务耗时和首次数据刷新仍需在部署后观察，本次本地测试不代表已更新服务器。
