# ADL 期间保证金优先

风险等级：R3。修复 Aster 的 ADL 自动暂停连带停止保证金划转的问题；资金检查继续先于 ADL 和策略工作执行。

## 行为与范围

- ADL 自动暂停时，原本运行的保证金平衡继续运行；active、blocked、completed hold 和重启均保留该状态。
- 用户主动暂停停止新划转，但不取消 ADL 应急和已有划转核对。事发前已暂停的组不会自动恢复资金。
- 旧 ADL 记录默认不推测原运行意图。“启动保证金平衡”通过既有写入鉴权，只读核验当前两账户及共同主账户后恢复资金；策略保持暂停。
- 资金继续状态存入现有 SQLite `kv`，绑定配对标识、版本及成员；不变更数据库结构。ADL 暂停与资金状态同事务写入；手动暂停以新代次撤销，发送前重新检查。配置版本变化使旧许可失效，删除配对同时删除许可。
- 新增接口 `POST /api/pairs/{id}/adl-margin-enable` 仅接受空对象，不接收交易参数。启动时复核配对、事件、控制记录、账户配置、绑定、连接及凭据；不清理原订单、资金 pending、冷却或退避记录。
- 保留保证金开关、实盘授权、维护/停机、资金未知结果防重发、账户身份、快照新鲜度、可划额度、资金预算和最终共享写入许可。

影响仅限内置 Aster 的配对/ADL/资金控制、只读状态及页面操作。没有改动划转金额算法、交易所协议、安装器或服务器部署。

## 回滚

回退到上一正式工作台版本即可恢复原行为。新控制记录是附加 `kv` 数据，旧版本忽略它；原账户、订单、划转与 ADL 事件结构保持兼容。回滚后 ADL 暂停会再次停止新划转，不能声称仍保留本次资金续跑能力。不得删除或伪造未知划转记录。
