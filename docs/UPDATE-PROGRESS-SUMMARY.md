### 第二阶段：后端实现 ✅

**核心文件**：

1. **deploy/release-common.sh** (+87 lines)
   ```bash
   init_progress_file()      # 初始化进度状态
   update_progress_file()    # 更新进度（500ms 间隔）
   cleanup_progress_file()   # 清理完成后的文件
   download_release_archive() # 集成进度写入
   ```

2. **server/update-service/progress.py** (新增 47 lines)
   ```python
   get_progress()      # 读取进度文件，检测超时
   stream_progress()   # SSE 流式推送
   ```

3. **server/app.mjs** (+9 lines)
   ```javascript
   app.get('/api/system/updates/progress', ...)  # SSE 端点
   ```

4. **server/update-service/updater.py** (+5 lines)
   - 更新完成后清理进度文件

**特性**：
- 原子写入避免读取不一致
- 5 分钟超时自动检测
- 完成或失败时自动结束流
- same-origin 安全限制

### 第三阶段：前端实现 ✅

**核心文件**：

1. **src/update-progress.ts** (新增 93 lines)

   - 速度格式化：2457600 → "2.4 MB/s"
   - ETA 格式化：125 → "2分钟"

2. **src/UpdateStatus.tsx** (+78 lines)
   - SSE 订阅（仅在 job running 时）
   - 实时进度条渲染

3. **src/update-types.ts** (+14 lines)
   - TypeScript 类型定义

4. **src/updates.css** (+56 lines)

   - 平滑过渡动画

## 🎯 功能特性

### 用户可见功能

1. **实时进度显示**
   - 5 个阶段的清晰提示
   - 百分比进度条（0-100%）
   - 平滑的动画过渡

2. **下载信息**
   - 实时速度显示（如 "2.4 MB/s"）
   - 预计剩余时间（如 "剩余约 30秒"）
   - 自适应单位（B/s, KB/s, MB/s）

3. **错误处理**
   - 网络失败时显示具体原因
   - 校验失败时显示摘要不匹配
   - 超时时自动检测并报告

4. **视觉设计**
   - 深色主题（#0A0D12, #0F131C）
   - 亮蓝色进度条（#38BDF8）
   - 等宽数字字体，防止跳动
   - 圆角 pill 形状

### 技术特性

1. **性能优化**
   - 500ms 最小写入间隔
   - SSE 仅在数据变化时推送
   - CSS transition 硬件加速

2. **安全边界**
   - same-origin SSE 端点
   - 临时目录隔离
   - 自动清理敏感文件

3. **向后兼容**
   - 旧服务器优雅降级
   - SSE 失败不影响更新
   - 进度缺失时正常安装

4. **错误恢复**
   - 5 分钟超时检测
   - 网络错误重试
   - 状态清理和重置


### 可以改进的地方

1. **首次提交前的完整性检查**
   - 应该在本地运行 `deploy/test-release.py`
   - 可以避免首次 CI 失败
   - 节省 CI 资源和时间

2. **嵌入脚本同步机制**
   - 考虑自动化同步工具
   - 或在修改时增加提示
   - 减少人工遗漏

3. **渐进式实现**
   - 可以先实现后端，测试通过
   - 再实现前端，分步验证
   - 减少首次提交的改动量

### 学到的经验

1. **嵌入脚本必须同步**
   - `install.sh` 和 `install-all.sh` 包含 `release-common.sh` 的副本
   - 修改源文件后必须同步嵌入版本
   - CI 会强制校验字节级一致性

2. **CI 测试的价值**
   - 本地测试可能遗漏环境差异
   - CI 提供标准化验证
   - 失败时快速定位问题
