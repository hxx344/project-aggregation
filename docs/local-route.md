# 本机 SSH 线路检测

当前工作台已停用自动 SSH 线路检测：顶栏只显示浏览器到服务器的 HTTP 响应延迟，不再请求本机 3101 端口，也不显示“SSH 直连”。使用 SSH 隧道无需启动下面的辅助程序。移除本机辅助接口的失败请求只减少诊断噪声，不代表服务器连接性能已经改善。

以下保留旧版检测工具的用法。线路检测针对打开网页的这台 Windows 电脑，不读取服务器访问交易所或项目的线路。

## 启动

电脑上需要 Node.js 24.15 或以上、Windows PowerShell，以及本项目源码。在本机项目目录执行一条命令，将 `服务器IP` 替换为 SSH 连接的实际 IP：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-local-route.ps1 -Server 服务器IP
```

SSH 不是默认 22 端口时，加上 `-SshPort 端口号`。保持检测程序运行，再打开 `http://hub.localhost:3100`。重复启动同一配置会复用已运行的检测程序；按 Ctrl+C 结束运行后，页面恢复为“线路未确认”。

该程序使用已有的 SSH 本地转发和 Clash Verge，不创建或重连隧道，不修改代理规则，也不注册开机服务。已有转发应监听本机 `127.0.0.1:3100`，例如：

```text
ssh -N -T -L 127.0.0.1:3100:127.0.0.1:3100 用户名@服务器IP
```

## 状态依据

- **SSH 直连**：本地 3100 端口属于唯一的 `ssh.exe`；该进程的目标连接与配置的服务器 IP、SSH 端口一致；连接源地址与当前路由匹配；出站接口是正常工作的物理网卡；Clash 本机控制接口可读且 TUN 明确关闭，没有该连接的代理链冲突。
- **线路未确认**：检测程序未启动、信息过期、目标不一致、跳板或多连接、虚拟接口、Clash TUN 开启、代理链冲突或检测失败。不会根据延迟、规则截图或健康接口成功就显示直连。

“SSH 直连”仅说明本机 SSH 连接的出站方式，不表示 VPN 软件已关闭，也不证明路由器或外部网络没有隧道。Clash 中的 `DIRECT` 规则表示分流意图；实际已有连接还需核对运行状态。

每 10 秒独立检测一次，检测耗时不计入服务器响应延迟。新一轮检测、离线或页面进入后台时清除旧结论，返回页面后重新检测。目前只支持上述 Windows SSH 入口；公网 HTTPS、其他端口、移动端或复杂跳板连接显示未确认。

## 本机接口边界

辅助程序只监听 `127.0.0.1:3101`，仅允许 `http://hub.localhost:3100` 对固定 `/route` 的只读请求。页面不携带工作台 Cookie、CSRF 令牌或代理密钥；辅助程序通过已有本机命名管道读取 Clash 状态，输出必要的线路摘要，不返回完整连接列表、配置或进程命令行。

只有本地 HTTP 工作台入口的 CSP 允许这个固定回环地址。浏览器若提示本地网络访问权限，需要允许后才能检测；无法访问时显示未确认。服务器无需配置本机 IP、Clash 密钥或额外服务。
