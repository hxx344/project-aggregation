# 工作台稳定性与加载性能验收（2026-09-22）

本轮修改工作台、Market Monitor 和 Asset Ledger。ASTER 报表后台生产与 CrossEx 来源刷新隔离沿用前一轮修复。本地修改和验证不代表服务器已完成升级。

## 已处理的问题

| 问题 | 处理结果 |
| --- | --- |
| 请求长时间不结束，登录、检查或刷新按钮持续等待 | 请求覆盖响应头和响应体的截止时间；取消能立即结束等待，迟到结果不能覆盖新数据；保存操作不自动重发 |
| 推送连接未关闭，但已停止送达消息 | 连续 40 秒没有有效消息后重建连接，并读取一次总览；隐藏或离线时停止连接，恢复后重新订阅 |
| 同一时刻多个刷新入口重复请求 | 总览与监控轮询合并进行中的请求 |
| 每秒刷新整个总览 | 按下一项源数据实际到期时间设置计时器；保留 CrossEx 等来源的更严格时效限制 |
| 每次检查重复发送其他项目和历史曲线 | 首次完整快照，后续只发送变化项目；空闲时发送轻量心跳，旧客户端继续使用原协议 |
| 历史曲线随无关状态更新反复计算 | 保留未变化数据的引用，图表跳过相同输入的重复渲染 |
| 静态资源原样下载并重复读取 | 公共文件 gzip、限容量缓存、ETag 和 304；API 与项目代理响应不进入此缓存 |
| 手动检查错误被后台总览刷新清掉 | 显示项目名称和具体原因，错误提示保留到手动关闭 |
| 项目 iframe 一直等待载入 | 30 秒后显示具体超时原因和重新载入入口 |
| 资产自动读取在切走页面后继续占用刷新状态 | 自动请求取消并立即释放状态；手动保存保持独立，旧请求不能释放新请求的状态 |
| 慢汇率请求阻塞账户读取 | 汇率分支与行情／账户分支独立执行；完成全部写入后才生成快照并释放所有者同步锁 |

## 量化结果

- 实际工作台 HTTP 静态响应（HTML、CSS、主程序和按需历史图表）：未压缩 **599,043 字节**，gzip **179,325 字节**，减少 **70.1%**。四个文件的条件请求均返回 304。该数字是下载正文大小，不是首屏耗时提升比例。
- 可复现的一分钟推送场景：4 个项目、90 个资产历史点，3 个项目每 5 秒检查、资产每 30 秒检查、每 15 秒心跳。43 条消息从 **258,086 字节**降至 **36,261 字节**，减少 **86.0%**。这是固定测试负载，不代表所有真实账户的流量比例。
- 重现推送测量：`node scripts/benchmark-overview.mjs`。

## 验证证据

- 工作台：103 项测试通过；类型检查与 Vite 生产构建通过。包含新旧推送协议的真实 HTTP 登录、配置更新、退出断流测试，以及数据删除、重排、版本缺口与重新连接测试。
- Market Monitor：546 项测试通过，6 项 Linux 安装器测试在 Windows 跳过；类型检查与 Windows 原生生产构建通过。首次并行测试有一个测试文件未通过，随后该文件单独 6 项与完整 552 项测试复查通过。
- Asset Ledger：47 项测试通过；Next.js 生产构建通过；生产模式集成测试通过。新增门控测试让汇率等待账户读取启动，证明慢汇率不会阻塞账户；继续验证旧值、原更新时间和历史快照保留。改动文件 lint 无错误，保留原有一条导航方式警告。
- 浏览器使用隔离的合成数据验收：首开只建立一条总览连接；静默连接会重建并触发读取；同时活动连接最多一条；源数据确实过期时仍显示过期；ASTER → Monitor → ASTER 来回切换，各模块各载入一次；挂起检查会结束等待并显示持久错误提示。
- 验证均使用 Windows 原生环境，没有使用 WSL；本轮未做 Linux 服务器部署验收。
