审查当前改动。全程只读，不修改文件、不提交。

1. 读取 `AGENTS.md`、`docs/code-review-standard.md`、`docs/code-review-checklist.md`。
2. 用 `git status` 和 `git diff HEAD` 确认改动范围；范围不明确时先问，不要自行扩大。
3. 按标准第 3 节判定风险等级，按 D1–D7 顺序审查：先语义与正确性，再失败路径，最后细节。
4. 每条意见按以下格式，一条一议：

```text
[P1] 文件:行
问题：
触发：
后果：
依据：L0xx 或标准条目
建议：
```

5. 同一根因的多个位置合并为一条，列出全部受影响位置；无法给出复现路径的标「待核实」，不按 P1 阻塞。
6. 末尾给结论：是否满足合并门槛、P0/P1 数量、哪些检查没有覆盖（不要声称运行了未运行的测试）。
