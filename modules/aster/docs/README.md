# Aster 5x 模块文档

币种公开数据与飞书通知统一在“币种监控中心”配置，使用方式、旧配置迁移和接口兼容说明见[币种监控中心](../../../docs/aster-monitoring.md)。

双子账户配对支持黄金 `XAUUSD1` 和白银 `XAGUSD1`。从工作台进入 Aster 5x，在新建配对组时选择标的；A 固定做多、B 固定做空，保存后保持暂停。已有组也可在“配对组设置”中修改交易标的，无需删除或重新创建配对组；组标识、两个成员及方向保持不变。

更换标的前先暂停配对组。已经手动持有目标标的时，无需先平仓：例如组里仍配置 `XAUUSD1`、实际已手动持有 `XAGUSD1`，可直接改为 `XAGUSD1`；服务端读取两侧实际白银持仓，将 A 的多仓、B 的空仓采纳为新底仓，数量不必相同，不沿用原黄金底仓数量。保存成功后继续保持暂停，原金额、策略和保证金设置保留，本次修改不会下单、平仓、调杠杆或划转。

人工归档的历史订单按原标的和原客户端编号重新核查，未发现订单或已终结且零成交时允许切换；观察记录继续保留，切换后仍检查旧订单是否出现迟到成交。实际待核对订单、旧循环遗留批次或增量、未明划转、活动挂单或读取异常仍需先处理；目标标的的账户方向、模式和杠杆要求保持不变。失败时保留原配置与运行记录。

切换会归档旧运行状态，原始成交与执行历史继续保留。同一配对组的当日成交额度和未确认成交限制跨标的累计，不会因切换而清零。

普通开仓、持仓核验、订单恢复和净持仓展示均使用本组标的。原黄金配对组无需迁移，缺省标的仍为黄金。单账户策略的默认品种和普通 `all` 范围保持原有配置。

配对白名单由 [`pair_symbols.py`](../trading/pair_symbols.py) 维护，前端通过已登录的 `GET /api/pairs/supported-symbols` 读取。普通开仓沿用每侧最低 500 USD1、默认单批 1000 USD1 和现有价差限制；实际数量步长、最小数量及最小名义金额仍取交易所规则；切换标的不自动放宽风控。

容量中继协议和缓存按标的隔离；调度和行情订阅也必须包含活跃配对组的标的。工作台仅从副服务器读取 `XAUUSD1`、`XAGUSD1` 的公开额度与杠杆档位，其他币种由主服务器低频直接读取（普通监控每币约 60 秒，策略所需额度按 2 秒基线、档位约 60 秒，受主服务器预算约束）。内置中继服务的新配置默认订阅 `XAUUSD1,XAGUSD1`，已有显式 `ASTER_RELAY_SYMBOLS` 不会被覆盖。若外部中继仍只提供黄金，需要在该中继的现有配置中加入 `XAGUSD1` 后更新服务。白银额度缺失或过期时只等待白银数据，不借用黄金额度。

新服务器安装独立中继、接入现有工作台及检查数据状态，见[额度中继部署说明](../../../docs/aster-relay.md)。中继安装器与连接导入工具均由当前工作台仓库发布。

已保存的白银配对组也会在启动时核验双向持仓、两侧实际杠杆、真实账户身份和挂单。目录中的“支持”表示软件支持，不代表已替用户完成实盘验证。所有新增回归使用隔离账户和模拟成交；本次未发送实盘订单或划转。

## 已移除的功能

单账户“多空循环”“仓位迁移”和配对组“循环”已移除。普通开仓、配对保证金平衡、ADL 应急处理、订单恢复和历史记录继续保留。

- **旧配置**：单账户的 `cycle`、`migration`、`migration_run_id` 在读取时忽略。账户原本处于启动状态且开启了旧功能时，加载后自动暂停，原因为“循环/仓位迁移功能已移除，请确认普通开仓设置后重新启动”；确认普通开仓设置后手动启动即可。自动暂停、手动暂停等系统保存会原样保留旧字段；用户保存设置或成功启动账户时才删除。配对组旧 `cycle` 配置读取时忽略，接口再提交循环字段会返回 422。配对组每次保存都在数据库保留一份旧版本可读的 `cycle` 设置：原来没有时写入关闭的默认值；改名、改保证金等保存保留原值；保存时开启普通加仓、启动配对组或切换标的，则改为关闭并让标的跟随当前标的，避免回滚后普通加仓与循环同时开启。
- **旧批次与持仓**：单账户仍有未完成的循环、迁移或迁移杠杆批次、迁移成交后核对、非零循环持仓或无法解析的循环记录时，账户保持暂停，启动、重试、修改设置、删除和组建配对都会被拒绝，典型提示为“旧循环/迁移批次待人工核对，功能已移除”。配对组的旧循环批次或增量进入待核对状态，提示“旧循环批次或增量待人工核对，循环功能已移除”，保证金平衡和 ADL 照常运行。程序不会自动平仓，也不会改写这些记录。
- **升级建议**：升级前先在旧版本停用循环与迁移，并等待进行中的批次完成。升级后若出现上述提示，可回到上一版本处理完旧批次，再重新升级。
- **历史数据**：数据库表、成交与执行记录、事件均保留；历史“循环检查”事件只读展示。
- **回滚**：本次改动没有新增或删除数据库表和字段，也没有删除旧记录；回滚到上一发布版本即可恢复旧功能。在新版本中由用户保存或启动过的账户已删除旧循环/迁移设置，回滚后按关闭的默认值显示；开启过普通加仓、启动过或切换过标的的配对组，其循环设置为关闭。需要使用旧功能时，在旧版本中重新开启。

单账户旧数据保护见 `tests/test_account_legacy.py`；配对组旧循环数据见 `tests/test_pair_cycle_order_recovery.py` 和 `tests/pair_legacy_fixtures.py`。

## ADL 应急减仓

从工作台进入 Aster 5x 的“两子账户配对”，选中配对组，在“ADL 应急处理”中点击“ADL 设置”。“ADL 后自动减仓”默认开启；单批名义金额上限默认 1000，可填写 1 到 1000000 之间的十进制金额，单位为每个待处理合约自己的计价币种。保存后使用真实的配对组配置，旧配对组缺少该配置时沿用默认值。

所有已绑定的实盘配对组都会监测 Aster 自动减仓（ADL），组暂停后也继续监听；实盘连接和执行仍受 `ASTER_ALLOW_LIVE=1` 控制。应急范围覆盖两个成员账户的全部 Aster 原生合约，包括手工仓位和普通策略标的之外的仓位。只有交易所已确认发生 ADL 成交的合约才进入处理；单纯仓位变化、普通强平或零成交的 `NEW_ADL` 通知不会授权应急下单。

发生 ADL 后，程序立即暂停配对策略，并读取两个账户的真实持仓。自动减仓开启时，对每个有 ADL 成交证据的合约，合计两账号全部多仓与全部空仓，仅分批关闭总数量较多的一侧，直到两侧总数量相同；不会为补齐少的一侧开新仓。其他没有 ADL 成交证据的合约不因此减仓。双向持仓和单向持仓按实际方向分别核对，原策略的未完成订单先核实，不重复发送旧策略请求。

每批按该轮新鲜持仓的标记价折算金额上限，数量向下取整，并受交易所数量步长、最小数量和市价单最大数量约束。这个名义金额上限不会为满足最小手数而放宽：上限低于合法一手时停止下单，明确报告金额上限或最小数量原因。实际市价成交金额会随成交价格变化。每批完成后重新读取现场，再计算下一批；剩余差额不足合法下单数量、账户或挂单状态无法核实等情况会保留现场并报告受阻。

关闭自动减仓后仍会监测 ADL、暂停配对策略、核实实际持仓并告警，但该次处理不会下单或撤单。已有原订单只进行有限查询，未知结果继续保留；手工将两账户相关合约的多空总数量调平后，程序会重新核实并记录完成。每次事件建立时固化开关和金额上限，处理及完成后的暂停观察期间按事件固定配置执行，不能通过修改配对组设置改写正在处理的事件。

ADL 来源使用私有 WebSocket 实时事件，并约每 60 秒通过 REST 补查；实时事件立即唤醒持久化和配对处理，不额外触发历史补查。重连仍会提前唤醒补查，限流时遵守重试等待时间，等待期间收到的重连请求不会丢失。首次建立监测基线从当前时间开始，不回扫旧历史并自动交易；已收到的实时成交事件会保留。页面“最近完整补查”只显示最近一次所有待查窗口成功完成的时间，读取页面不会刷新这个时间，失败或仍有待查窗口时不会伪装成新近成功。事件、待查窗口和减仓批次写入持久记录，重复事件不会重复计量；重启后继续核对原批次，结果未知的订单不会换编号重发。

原订单最多实际查询三次；满 120 秒安全观察窗口后，读取新的完整持仓和挂单，自动减仓开启时才按现场剩余差额准备新的减仓批次，关闭时继续等待手工平衡。原单仍明确标记为未知，不伪造成零成交或成功。若允许自动处理且发生撤单，观察窗口从最近可能发送撤单的时刻重新计算。仓位的交易所更新时间必须覆盖已确认的 ADL 成交；两份同时滞后的 REST 响应不能作为处理完成的依据。

为减少 ADL 现场的重复额度消耗，每个账户的持仓模式证据在同一事件内最多复用 15 秒，重启、重连或账户配置事件会使其失效。需要挂单核验时，事件及历史原订单涉及的标的不超过 5 个则逐标的查询，更多时读取全账户挂单；逐次核验响应标的、方向和订单内容。每次现场仍读取账户和完整持仓，持仓或挂单方向与模式证据矛盾时阻塞处理。

保证金平衡的候选预检复用同次资金快照中的可划额度，缺失时才回退单次上限；存在但无效的额度会阻塞处理。该预检只能提前判定本轮不划转，实际划转前仍重新核验账户归属、余额和交易所可划额度。

“ADL 应急处理”展示监测状态、事件固定配置和处理进度；有事件记录时可点击“查看处理报告”，核对原 ADL 订单、两个账户的处理前后持仓、减仓批次、未知订单和最终残差。打开报告只读取已有记录，不触发交易所查询或交易。

飞书发送首次现场、受阻和完成报告，包含两个账户的相关持仓、减仓批次及处理结果，并注明本次开关和金额上限。报告仍受币种监控中心的飞书全局开关控制，不依赖可选的单币通知类型；可从“查看通知设置”检查通知配置。处理完成后配对组继续暂停；核对报告和现场后需明确点击启动，重新核验并采纳当前策略底仓。处理中重复点击暂停不会取消应急处理或改动其配置版本。

完成时若仍有未知回报，暂停期间每 10 秒核对现场；再次出现相关合约净差时，建立关联前次事件的新处理记录，按事件配置继续只减多余仓位或等待手工处理，并发送报告。明确手动启动后结束该暂停观察，重新核验的当前仓位成为后续策略底仓。

此处说明当前仓库的软件功能，不代表已部署到服务器。模块随工作台统一发布，服务器由用户更新。

ADL 配置校验见 `tests/test_adl_config.py`；配置与报告接口见 `tests/test_adl_api.py`；解析与续查见 `tests/test_adl_events.py`；实际持仓读取见 `tests/test_adl_exchange.py`；金额上限、自动开关、恢复及监测健康时间见 `tests/test_adl_controller.py`；调度、交易拦截和启动边界见 `tests/test_adl_integration.py`。
