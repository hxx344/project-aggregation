# Aster 5x 模块文档

币种公开数据与飞书通知统一在“币种监控中心”配置，使用方式、旧配置迁移和接口兼容说明见[币种监控中心](../../../docs/aster-monitoring.md)。

双子账户配对组只做两侧 USD1 保证金平衡和 ADL 应急处理，不再开仓或平仓。配对组支持黄金 `XAUUSD1` 和白银 `XAGUSD1`。从工作台进入 Aster 5x，在新建配对组时选择标的；A 固定做多、B 固定做空，保存后保持暂停。需先开启保证金平衡才能启动配对组。

更换标的前先暂停配对组。切换只修改配置，不读取或采纳持仓，也不会下单、平仓、调杠杆或划转；切换后继续保持暂停。原始成交与执行历史继续保留。未明划转、ADL 未完成或旧版本遗留的开仓批次仍需先处理；失败时保留原配置与运行记录。

删除配对组只解除两个子账户的绑定，不要求先平仓：两个账户的持仓保留，解除后不再自动平衡保证金。配对组运行中、ADL 未完成、保证金划转尚未核实或仍有旧版本遗留的开仓批次时不能删除。

配对白名单由 [`pair_symbols.py`](../trading/pair_symbols.py) 维护，前端通过已登录的 `GET /api/pairs/supported-symbols` 读取。容量中继协议和缓存按标的隔离。工作台仅从副服务器读取 `XAUUSD1`、`XAGUSD1` 的公开额度与杠杆档位，其他币种由主服务器低频直接读取（普通监控每币约 60 秒，单账户策略所需额度按 2 秒基线、档位约 60 秒，受主服务器预算约束）。内置中继服务的新配置默认订阅 `XAUUSD1,XAGUSD1`，已有显式 `ASTER_RELAY_SYMBOLS` 不会被覆盖。

新服务器安装独立中继、接入现有工作台及检查数据状态，见[额度中继部署说明](../../../docs/aster-relay.md)。中继安装器与连接导入工具均由当前工作台仓库发布。

## 已移除的功能

### 配对组普通开仓

配对组的普通开仓（成对开仓、补单、升杠杆、订单恢复、底仓采纳与空仓核对）已移除。单账户普通开仓不受影响。

- **旧配置**：已保存配对组的 `ordinary` 字段保留在数据库中，保证回滚后旧版本仍能读取：新建、修改设置或切换标的时写为关闭及该标的默认值，启动、暂停等其他保存只把其中的开关改为关闭；接口再提交 `ordinary` 返回 422。原为普通开仓模式的配对组按仅保证金平衡运行。
- **旧批次**：仍有旧版本留下的未完成批次（`pending`）或订单观察记录（`recovery_watch`）的配对组进入待核对状态，不启动、不修改、不删除，也不自动核对这些订单；需回到上一版本处理完再升级。工作台更新的激活检查本来就会拒绝带这类记录的升级。
- **接口**：`/api/pairs/{id}/margin-only`、`recovery-*`、`baseline-*`、`reconcile-flat` 已删除；汇总接口不再提供“实盘今日成交量”指标。
- **回滚**：没有新增或删除数据库表和字段；回滚到上一发布版本即可恢复配对开仓。升级后保存过（含启动或暂停）的配对组，回滚后普通开仓为关闭，需要时在旧版本中重新开启；升级后从未保存过的旧配对组保持原开关。

### 循环与仓位迁移

单账户“多空循环”“仓位迁移”和配对组“循环”已移除。单账户普通开仓、配对保证金平衡、ADL 应急处理和历史记录继续保留。

- **旧配置**：单账户的 `cycle`、`migration`、`migration_run_id` 在读取时忽略。账户原本处于启动状态且开启了旧功能时，加载后自动暂停，原因为“循环/仓位迁移功能已移除，请确认普通开仓设置后重新启动”；确认普通开仓设置后手动启动即可。自动暂停、手动暂停等系统保存会原样保留旧字段；用户保存设置或成功启动账户时才删除。配对组旧 `cycle` 配置读取时忽略，接口再提交循环字段会返回 422。配对组每次保存都在数据库保留一份旧版本可读的 `cycle` 设置：原来没有时写入关闭的默认值；改名、改保证金等保存保留原值；启动配对组或切换标的时，则改为关闭并让标的跟随当前标的，避免回滚后普通加仓与循环同时开启。
- **旧批次与持仓**：单账户仍有未完成的循环、迁移或迁移杠杆批次、迁移成交后核对、非零循环持仓或无法解析的循环记录时，账户保持暂停，启动、重试、修改设置、删除和组建配对都会被拒绝，典型提示为“旧循环/迁移批次待人工核对，功能已移除”。配对组的旧循环批次或增量进入待核对状态，提示“旧循环批次或增量待人工核对，循环功能已移除”，保证金平衡和 ADL 照常运行。程序不会自动平仓，也不会改写这些记录。
- **升级建议**：升级前先在旧版本停用循环与迁移，并等待进行中的批次完成。升级后若出现上述提示，可回到上一版本处理完旧批次，再重新升级。
- **历史数据**：数据库表、成交与执行记录、事件均保留；历史“循环检查”事件只读展示。
- **回滚**：本次改动没有新增或删除数据库表和字段，也没有删除旧记录；回滚到上一发布版本即可恢复旧功能。在新版本中由用户保存或启动过的账户已删除旧循环/迁移设置，回滚后按关闭的默认值显示；开启过普通加仓、启动过或切换过标的的配对组，其循环设置为关闭。需要使用旧功能时，在旧版本中重新开启。

单账户旧数据保护见 `tests/test_account_legacy.py`；配对组旧循环数据见 `tests/test_pair_cycle_order_recovery.py` 和 `tests/pair_legacy_fixtures.py`。

## ADL 应急减仓

从工作台进入 Aster 5x 的“两子账户配对”，选中配对组，在“ADL 应急处理”中点击“ADL 设置”。“ADL 后自动减仓”默认开启；单批名义金额上限默认 1000，可填写 1 到 1000000 之间的十进制金额，单位为每个待处理合约自己的计价币种。保存后使用真实的配对组配置，旧配对组缺少该配置时沿用默认值。

所有已绑定的实盘配对组都会监测 Aster 自动减仓（ADL），组暂停后也继续监听；实盘连接和执行仍受 `ASTER_ALLOW_LIVE=1` 控制。应急范围覆盖两个成员账户的全部 Aster 原生合约，包括手工仓位和普通策略标的之外的仓位。只有交易所已确认发生 ADL 成交的合约才进入处理；单纯仓位变化、普通强平或零成交的 `NEW_ADL` 通知不会授权应急下单。

发生 ADL 后，程序立即暂停配对策略，并读取两个账户的真实持仓。自动减仓开启时，对每个有 ADL 成交证据的合约，合计两账号全部多仓与全部空仓，仅分批关闭总数量较多的一侧，直到两侧总数量相同；不会为补齐少的一侧开新仓。其他没有 ADL 成交证据的合约不因此减仓。双向持仓和单向持仓按实际方向分别核对，原策略的未完成订单先核实，不重复发送旧策略请求。

ADL 自动暂停只暂停交易策略：事发前已运行的保证金自动平衡继续优先检查和划转，不因应急受阻、等待、处理完成后的暂停观察或进程重启而停止。资金继续运行的状态单独持久保存，不改变 ADL 冻结的配置版本；已有未知策略订单也不会阻挡资金任务。保证金自己的未知划转、交易所限流与可划额度、身份校验、维护及停机限制继续生效。

手动点击“暂停”仍会停止新的保证金划转，已提交划转继续核对，ADL 应急本身继续处理；事发前已被手动暂停的组不会因 ADL 自动恢复资金。ADL 暂停期间可点击“启动保证金平衡”，核验账户归属后只恢复资金管理，不启动交易策略、不改写持仓、原划转或 ADL 事件。旧版本的事件没有保存事发前运行意图，升级后保持停止，需通过这个入口明确恢复。页面分别显示策略暂停与保证金运行状态。

每批按该轮新鲜持仓的标记价折算金额上限，数量向下取整，并受交易所数量步长、最小数量和市价单最大数量约束。这个名义金额上限不会为满足最小手数而放宽：某个合约的上限低于合法一手时，该合约停止下单，明确报告金额上限或最小数量原因。实际市价成交金额会随成交价格变化。每批完成后重新读取现场，再计算下一批。各合约独立推进：某个合约剩余差额不足合法下单数量、金额上限不足一手，或成功读取的交易所规则显示该合约暂停交易、已不在列表中或不支持市价单时，只保留该合约的尾差和受阻原因，不会为消除尾差而放大订单；其他有 ADL 成交证据且能严格减少净差的合约继续分批处理。其他合约仍在处理期间，事件保持“正在处理”，受阻合约写在处理原因中，不单独转为受阻状态或发送受阻通知；只剩受阻合约时才转为受阻并通知。只要仍有合约受阻，事件就不会记录完成，处理状态和报告列出受阻合约、尾差及原因，手工调平后重新核实才记录完成。账户身份、挂单状态无法核实、ADL 成交尚未反映到持仓、交易规则读取失败或响应异常、现场冲突等整体不确定情况，仍暂停所有合约的减仓并报告受阻；处理时限、批次数上限、交易所拒单或连续三批未成交引起的停止同样覆盖所有合约。事件记录中的逐合约进度（`symbol_progress`）只是持久审计数据，不授权下单，也不在页面单独展示；受阻合约通过处理原因展示。

关闭自动减仓后仍会监测 ADL、暂停配对策略、核实实际持仓并告警，但该次处理不会下单或撤单。已有原订单只进行有限查询，未知结果继续保留；手工将两账户相关合约的多空总数量调平后，程序会重新核实并记录完成。每次事件建立时固化开关和金额上限，处理及完成后的暂停观察期间按事件固定配置执行，不能通过修改配对组设置改写正在处理的事件。

ADL 来源使用私有 WebSocket 实时事件，并约每 60 秒通过 REST 补查；实时事件立即唤醒持久化和配对处理，不额外触发历史补查。重连仍会提前唤醒补查，限流时遵守重试等待时间，等待期间收到的重连请求不会丢失。首次建立监测基线从当前时间开始，不回扫旧历史并自动交易；已收到的实时成交事件会保留。页面“最近完整补查”只显示最近一次所有待查窗口成功完成的时间，读取页面不会刷新这个时间，失败或仍有待查窗口时不会伪装成新近成功。事件、待查窗口和减仓批次写入持久记录，重复事件不会重复计量；重启后继续核对原批次，结果未知的订单不会换编号重发。

原订单最多实际查询三次；满 120 秒安全观察窗口后，读取新的完整持仓和挂单，自动减仓开启时才按现场剩余差额准备新的减仓批次，关闭时继续等待手工平衡。原单仍明确标记为未知，不伪造成零成交或成功。若允许自动处理且发生撤单，观察窗口从最近可能发送撤单的时刻重新计算。仓位的交易所更新时间必须覆盖已确认的 ADL 成交；两份同时滞后的 REST 响应不能作为处理完成的依据。

为减少 ADL 现场的重复额度消耗，每个账户的持仓模式证据在同一事件内最多复用 15 秒，重启、重连或账户配置事件会使其失效。需要挂单核验时，事件及历史原订单涉及的标的不超过 5 个则逐标的查询，更多时读取全账户挂单；逐次核验响应标的、方向和订单内容。每次现场仍读取账户和完整持仓，持仓或挂单方向与模式证据矛盾时阻塞处理。

保证金平衡的候选预检复用同次资金快照中的可划额度，缺失时才回退单次上限；存在但无效的额度会阻塞处理。该预检只能提前判定本轮不划转，实际划转前仍重新核验账户归属、余额和交易所可划额度。

“ADL 应急处理”展示监测状态、事件固定配置和处理进度；有事件记录时可点击“查看处理报告”，核对原 ADL 订单、两个账户的处理前后持仓、减仓批次、未知订单和最终残差。打开报告只读取已有记录，不触发交易所查询或交易。

飞书发送首次现场、受阻和完成报告，包含两个账户的相关持仓、减仓批次及处理结果，并注明本次开关和金额上限。报告仍受币种监控中心的飞书全局开关控制，不依赖可选的单币通知类型；可从“查看通知设置”检查通知配置。处理完成后配对组继续暂停；核对报告和现场后需明确点击启动。处理中重复点击暂停不会取消应急处理或改动其配置版本。

完成时若仍有未知回报，暂停期间每 10 秒核对现场；再次出现相关合约净差时，建立关联前次事件的新处理记录，按事件配置继续只减多余仓位或等待手工处理，并发送报告。明确手动启动后结束该暂停观察。

此处说明当前仓库的软件功能，不代表已部署到服务器。模块随工作台统一发布，服务器由用户更新。

本次资金优先修复的范围、验证与回滚见[ADL 期间保证金优先](../../../docs/aster-adl-margin-priority.md)。

ADL 配置校验见 `tests/test_adl_config.py`；配置与报告接口见 `tests/test_adl_api.py`；解析与续查见 `tests/test_adl_events.py`；实际持仓读取见 `tests/test_adl_exchange.py`；金额上限、自动开关、恢复及监测健康时间见 `tests/test_adl_controller.py`；调度、交易拦截和启动边界见 `tests/test_adl_integration.py`。
