# Aster 5x 模块文档

币种公开数据与飞书通知统一在“币种监控中心”配置，使用方式、旧配置迁移和接口兼容说明见[币种监控中心](../../../docs/aster-monitoring.md)。

双子账户配对支持黄金 `XAUUSD1` 和白银 `XAGUSD1`。从工作台进入 Aster 5x，在新建配对组时选择标的；A 固定做多、B 固定做空，保存后保持暂停。已有组也可在“配对组设置”中修改交易标的，无需删除或重新创建配对组；组标识、两个成员及方向保持不变。

更换标的前先暂停配对组。已经手动持有目标标的时，无需先平仓：例如组里仍配置 `XAUUSD1`、实际已手动持有 `XAGUSD1`，可直接改为 `XAGUSD1`；服务端读取两侧实际白银持仓，将 A 的多仓、B 的空仓采纳为新底仓，数量不必相同，不沿用原黄金底仓数量。保存成功后继续保持暂停，原金额、策略和保证金设置保留，本次修改不会下单、平仓、调杠杆或划转。

人工归档的历史订单按原标的和原客户端编号重新核查，未发现订单或已终结且零成交时允许切换；观察记录继续保留，切换后仍检查旧订单是否出现迟到成交。实际待核对订单、尚未减回的循环新增仓位、未明划转、活动挂单或读取异常仍需先处理；目标标的的账户方向、模式和杠杆要求保持不变。失败时保留原配置与运行记录。

切换会归档旧运行状态，原始成交与执行历史继续保留；成本按当前标的分别显示，切回原标的仍可查看对应成本。同一配对组的当日成交额度和未确认成交限制跨标的累计，不会因切换而清零。

普通开仓、独立循环、持仓核验、订单恢复和净持仓展示均使用本组标的。原黄金配对组无需迁移，缺省标的仍为黄金。单账户策略的默认品种、普通 `all` 范围和迁移目标保持原有配置。

配对白名单由 [`pair_symbols.py`](../trading/pair_symbols.py) 维护，前端通过已登录的 `GET /api/pairs/supported-symbols` 读取。普通开仓沿用每侧最低 500 USD1、默认单批 1000 USD1 和现有价差限制；实际数量步长、最小数量及最小名义金额仍取交易所规则。循环参数需要按所选品种的实际价差配置，切换标的不自动放宽风控。

容量中继协议和缓存按标的隔离；调度和行情订阅也必须包含活跃配对组的标的。工作台仅从副服务器读取 `XAUUSD1`、`XAGUSD1` 的公开额度与杠杆档位，其他币种由主服务器低频直接读取（普通监控每币约 60 秒，策略所需额度按 2 秒基线、档位约 60 秒，受主服务器预算约束）。内置中继服务的新配置默认订阅 `XAUUSD1,XAGUSD1`，已有显式 `ASTER_RELAY_SYMBOLS` 不会被覆盖。若外部中继仍只提供黄金，需要在该中继的现有配置中加入 `XAGUSD1` 后更新服务。白银额度缺失或过期时只等待白银数据，不借用黄金额度。

新服务器安装独立中继、接入现有工作台及检查数据状态，见[额度中继部署说明](../../../docs/aster-relay.md)。中继安装器与连接导入工具均由当前工作台仓库发布。

已保存的白银配对组也会在启动时核验双向持仓、两侧实际杠杆、真实账户身份和挂单。目录中的“支持”表示软件支持，不代表已替用户完成实盘验证。所有新增回归使用隔离账户和模拟成交；本次未发送实盘订单或划转。

## ADL 应急减仓

所有已绑定的实盘配对组都会监测 Aster 自动减仓（ADL），组暂停后也继续监听；实盘连接和执行仍受 `ASTER_ALLOW_LIVE=1` 控制。应急范围覆盖两个成员账户的全部 Aster 原生合约，包括手工仓位和普通策略标的之外的仓位。只有交易所已确认发生 ADL 成交的合约才进入处理；单纯仓位变化、普通强平或零成交的 `NEW_ADL` 通知不会授权应急下单。

发生 ADL 后，程序立即暂停配对策略，并读取两个账户的真实持仓。对每个有 ADL 成交证据的合约，合计两账号全部多仓与全部空仓，仅分批关闭总数量较多的一侧，直到两侧总数量相同；不会为补齐少的一侧开新仓。其他没有 ADL 成交证据的合约不因此减仓。双向持仓和单向持仓按实际方向分别核对，原策略的未完成订单先核实，不重复发送旧策略请求。

默认每批市价减仓的名义金额不超过 1000 个该合约的计价资产单位，并受交易所数量步长、最小数量和市价单最大数量约束；若最小合法一手的名义金额已超过 1000，则允许按该最小合法数量处理。每批完成后重新读取现场，再计算下一批，避免用旧仓位连续减仓。剩余差额不足合法下单数量、账户或挂单状态无法核实等情况会保留现场并报告受阻。

ADL 来源使用私有 WebSocket 实时事件，并约每 60 秒通过 REST 补查；连接状态变化也会唤醒补查，限流时遵守重试等待时间。首次建立监测基线从当前时间开始，不回扫旧历史并自动交易；已收到的实时成交事件会保留。事件、待查窗口和减仓批次写入持久记录，重复事件不会重复计量；重启后继续核对原批次，结果未知的订单不会换编号重发。

原订单最多实际查询三次；满 120 秒安全观察窗口后，读取新的完整持仓和挂单，按现场剩余差额准备新的减仓批次。原单仍明确标记为未知，不伪造成零成交或成功。若发生撤单，观察窗口从最近可能发送撤单的时刻重新计算。仓位的交易所更新时间必须覆盖已确认的 ADL 成交；两份同时滞后的 REST 响应不能作为处理完成的依据。

飞书发送首次现场、受阻和完成报告，包含两个账户的相关持仓、减仓批次及处理结果。报告仍受币种监控中心的飞书全局开关控制，不依赖可选的单币通知类型。处理完成后配对组继续暂停，旧循环不会自动恢复平仓；核对现场后需明确点击启动，重新核验并采纳当前策略底仓。处理中重复点击暂停不会取消应急处理或改动其配置版本。

完成时若仍有未知回报，暂停期间每 10 秒核对现场；再次出现相关合约净差时，建立关联前次事件的新处理记录，继续只减多余仓位并发送报告。明确手动启动后结束该暂停观察，重新核验的当前仓位成为后续策略底仓。

此处说明当前仓库的软件功能，不代表已部署到服务器。模块随工作台统一发布，服务器由用户更新。

ADL 解析与续查测试见 `tests/test_adl_events.py`，调度、交易拦截和启动边界见 `tests/test_adl_integration.py`，实际持仓读取与减仓规则见 `tests/test_adl_exchange.py`。
