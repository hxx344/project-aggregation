# 工序产物模板

每个产物文件顶部统一写：任务号、工序、负责人、时间、状态（完成 / 阻塞 / 打回）。结论先行，证据在后，不写过程流水账。

## 01-brief.md（PM：需求澄清）

- 老板原话（引用）
- 目标（一句话）
- 范围内 / 范围外
- 验收标准（可判定条目，编号 A1、A2…）
- 授权与风险（只读 / 可改代码 / 可提交 / 是否 R3）
- 约束（时间、模块、规则引用）

## 02-design.md（ARCH：技术方案）

- 方案概述（1–3 段）
- 改动分级：R1 / R2 / R3（依据仓库标准）+ 理由
- 受影响路径与契约
- 最小检查集（命令 + 预期）
- 回滚方案（R2/R3 必填）
- 风险与未知项

## 03-dev.md（DEV：实现与自测）

- 改动清单（文件 → 改了什么）
- 自测记录：命令 → 真实输出摘要 → 结论
- 未运行的检查 + 原因
- 偏离方案之处（没有就写「无」）

## 04-test.md（QA：独立测试）

- 测试策略（如何独立于开发结论）
- 逐条验证：验收标准 → 命令 → 真实输出 → 通过 / 不通过
- 缺陷列表（P0/P1/P2，含复现命令）
- 结论：放行 / 打回

## 05-review.md（REV：独立审查）

- 审查范围（diff / 文件 / 产物）
- 结论：可合并 / 需修改 / 不可合并
- 问题清单：P0 / P1 / P2（位置 + 依据 + 建议）
- 未验证项与理由
- 与 04 的分歧（没有就写「无」）

## 06-release.md（REL：发布与文档）

- 交付物清单
- 变更说明（面向使用者）
- 升级 / 部署 / 回滚步骤（可执行）
- 文档影响与已更新文档
- 待老板授权动作（提交 / 推送 / 部署）

## 07-acceptance.md（PM：终验关单）

- 验收标准逐条判定：A1 通过/不通过 → 证据（指向前序产物）
- 遗留 P2 与后续任务建议
- 关单结论：通过 / 回退到第 N 道
